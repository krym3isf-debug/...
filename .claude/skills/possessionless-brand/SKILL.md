# Possessionless Brand Skill

This is an index, not a dump. Each knowledge file below is independent and small — read only the ones relevant to the current task, so you're not paying token cost for unrelated brand knowledge.

## Knowledge files

| File | Contains | Load when... |
|---|---|---|
| `knowledge/brand.md` | Identity, aesthetic, positioning, voice/tone rules | Writing any customer-facing copy, naming things, making a design call |
| `knowledge/products.md` | Product catalog notes, categories, fit/sizing notes | Working on product pages, PDPs, catalog structure |
| `knowledge/website.md` | Website structural rules, tech stack, do/don't list | Any Shopify/theme/frontend work |
| `knowledge/creative-framework.md` | TOF/MOF/BOF funnel framework for ad creative | Any ad creative review, briefing, or classification task |
| `knowledge/campaign-history.md` | Historical Meta Ads tests, learnings (append-only) | Researching what's been tried before |
| `knowledge/current-performance.md` | Latest performance snapshot (overwritten as new data arrives) | Any "how are we doing right now" question |
| `knowledge/tracking.md` | Meta Pixel IDs, Triple Whale setup, what NOT to touch | Any task touching pixels, tracking, attribution, GTM |

For deep Meta Ads *analysis methodology* (metrics, evaluation priority, classification logic), use the separate `meta-ads-expert` skill — it's kept separate because it's a reasoning framework, not brand fact data, and not every marketing task needs it loaded.

## Rule for updating this skill

When the user provides new source material, update the *one* file it belongs in. Don't merge everything into one giant file — that defeats the point of loading only what's needed. If a new category of knowledge doesn't fit an existing file, create a new small file and add a row to the table above.
